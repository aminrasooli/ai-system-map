> deliberately not protected.

## What is covered

| Path | Contains | Frequency | Notes |
|---|---|---|---|
| `/home/developer/projects` | Source trees and uncommitted working state | Daily | Includes work not yet pushed anywhere |
| `/home/developer/services` | Deployed application trees and their data | Daily | Includes the SQLite database file |
| `/etc` | System configuration | Daily | Service unit definitions live here |

## What is NOT covered

| Path or data | Why not covered | Recoverable another way? |
|---|---|---|
| Container images | Rebuildable from their definitions | yes — rebuild |
| Package caches | Reproducible from the package repository | yes — reinstall |
| `/home/developer/backups` | Local staging only; contents already uploaded | yes — from remote storage |
| Build output directories | Regenerated by a build | yes — rebuild |
| System journal history | Operational logs, not business data | no — accepted loss |

The last row is accepted data loss and is intentional.

## Recovery objectives

| Objective | Target | Actual | Notes |
|---|---|---|---|
| Recovery point (how much data may be lost) | 24 hours | Up to 24 hours | Bounded by the daily schedule |
| Recovery time (how long to get back) | 4 hours | About 2 hours measured | Measured during the 2026-01-12 test |

## Work in progress

| Location | Protected by | Exposure window |
|---|---|---|
| Uncommitted working trees | Daily filesystem backup | Up to 24 hours |
| Committed but unpushed | Daily filesystem backup | Up to 24 hours |

Work created and lost within a single day is not recoverable. For anything
that matters, push it or run the backup by hand.

## Dependencies

| Dependency | Where it lives | Available during a bare-metal recovery? |
|---|---|---|
| Backup repository location | Documented in this file | yes |
| Repository password | Team password manager | yes |
| Encryption passphrase | Team password manager | yes |
| The restore procedure itself | Private repository, plus a printed copy | yes |

> If any dependency were stored only on this machine, recovery would not be
> proven. All four are held independently.
